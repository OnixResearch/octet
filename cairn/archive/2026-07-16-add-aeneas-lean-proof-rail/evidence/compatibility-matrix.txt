# Aeneas compatibility matrix evidence

Requirement: `r[octet.aeneas_lean_proof_rail.pin_upgrade_matrix]`

Added the typed Nickel matrix
`standards/proof-rails/aeneas-lean/compatibility-matrix.ncl` and generated
`generated/compatibility-matrix.json`. The matrix names all upgrade dimensions
(Aeneas, Charon, rustc, Lean, Aeneas library, schema, and provider profile) and
nine canaries: positive provider, false/vacuous theorem, partial output,
borrow-check bypass, opacity/model trust closure, target drift, freshness,
unsupported feature, and exported-evidence tamper.

The Nix proof-rail manifest check now typechecks and exports the matrix,
compares the generated bytes, checks the expected positive/rejection counts and
category inventory, and requires every named Rust test function to exist. This
is a deterministic gate over the pure validator canaries; it does not claim
that live upstream tools were executed.

```text
$ nix develop -c nickel typecheck standards/proof-rails/aeneas-lean/compatibility-matrix.ncl
success

$ nix build .#checks.x86_64-linux.proof-rail-manifest --no-link -L
success (remote-builder connection warning is non-blocking; local derivation passed)

$ nix develop -c cargo test -p octet-standards --lib aeneas -- --nocapture
... test result: ok. 13 passed; 0 failed
```
