# Design

## Success contract

Goal: make Octet's existing warning debt reviewable and fail closed on newly introduced self-check findings without weakening lint policy.

Observable completion evidence:

- canonical JSON output succeeds and every finding locator is repository-relative;
- absolute paths inside the workspace normalize deterministically, while outside-root and parent-traversal paths fail closed;
- the checked-in baseline exactly matches the post-cleanup canonical run with zero new and zero stale IDs;
- the inventory records 2,670 accepted warning occurrences and 1,820 unique stable identities after `negated_predicate` falls from one finding to zero;
- a hermetic source mutation introduces one warning, exits `1`, and reports exactly one new baseline ID;
- existing malformed-metadata and Cargo-child failures still exit `2`;
- focused tests, policy freshness, traceability, Nextest, Clippy, and the broad compatible-system flake gate pass.

False completion includes scraping human stderr, accepting only a numeric total, disabling lints, broad `allow` attributes, weakening repository-relative path validation, treating stale IDs as new failures, regenerating the baseline without review, or claiming accepted debt is correct or release-ready.

## Approach registry

| Family | Mechanism | State | Evidence / blocker |
| --- | --- | --- | --- |
| exact existing baseline | Reuse `--write-baseline` and `--baseline` stable-ID semantics | active | Existing positive, drift, rename, and incomplete-run tests pass |
| count-only ceiling | Fail when the total exceeds 2,670 | rejected | One finding can replace another without increasing the total |
| human-output parser | Scrape rendered diagnostics into a separate inventory | falsified | Human rendering is not the structured finding contract and loses stable IDs |
| custom warning database | Add a second parser/schema beside `cargo-octet` baseline | rejected | Duplicates established authority and creates drift |
| deny all current warnings | Promote the entire catalog immediately | rejected | Existing debt would block every change and incentivize blanket suppression |
| relax path domain | Permit absolute finding locators | rejected | Leaks host paths and breaks portable evidence identity |

## Functional core and shell

Pure normalization cores receive the explicit workspace root plus a reported Cargo path or diagnostic message. The locator core returns a `RootRelativePath` display string for an in-root absolute or already-relative path and rejects absolute paths outside the root, empty paths, and traversal. The message core replaces only exact workspace-root substrings before stable-ID construction so host checkout and Nix sandbox identities agree. The runner shell supplies the discovered workspace root and propagates errors before baseline or artifact mutation.

The existing baseline writer/evaluator remains the decision core for accepted, new, and stale stable IDs. The Nix shell supplies immutable source and a writable negative copy; it does not implement an alternative comparison algorithm.

## Baseline and inventory

`standards/self-check-warning-budget/octet-baseline.json` is generated by the packaged runner from the canonical `--workspace --lib` scope after the bounded cleanup. It keeps the existing schema, metadata, BLAKE3 baseline hash, stable/semantic IDs, lint, domain, severity, relative locator, position, message, and crate context. Repeated occurrences of one stable identity are stored once because admission compares identity sets; the separate inventory retains the 2,670 occurrence count.

`docs/self-check-warning-budget.md` records the grouped pre/post inventory and review procedure. The baseline remains the machine-readable source; prose counts are checked by the hermetic gate and do not authorize silent baseline refresh.

## Permanent gate

The existing `cargo-octet-self-check` derivation runs JSON output with the checked-in baseline and artifact directory. It requires warning-only or clean status, zero errors, zero new IDs, zero stale IDs, the exact accepted total, repository-relative locators, and no `negated_predicate` finding.

A writable negative copy injects one behavior-preserving, intentionally negated predicate binding into a selected workspace library. The same runner and baseline must exit `1`; `status.json` must report exactly one new ID and no integration failure. Existing malformed metadata and non-zero Cargo-child cases remain separate exit-`2` assertions.

## Claims and budget

The accepted baseline proves only stable-ID membership for one pinned local static-lint run. It does not prove warning correctness, low false-positive rate, test/binary/example coverage, dependency behavior, runtime safety, whole-program correctness, lint completeness, or release eligibility.

The bounded search budget is four source/audit passes, one canonical inventory run, one advisory audit, and three implementation/validation rounds. Allowed terminal outcomes are validated, blocked with the exact path or baseline defect, exhausted, or user-decision-required.
