## Why

Function-address reports start in Octet as Rust source-shape evidence, but the durable stack interchange boundary should be Kamacite Preserves receipts. Keeping Octet JSON as the long-term authority would duplicate identity rules and invite ordering/stringly-typed drift across Valence, Mantle, and Cairn.

## What Changes

- Keep `function-addresses.json` as an operator/debug projection.
- Add an explicit Octet-to-Kamacite handoff contract for Preserves-backed function-address receipts.
- Ensure Octet emits the typed fields Kamacite needs for canonical Preserves encoding: producer metadata, source envelope identity, relative path, byte spans, function address, dependency identity kind, and non-claims.
- Add positive and negative fixtures for handoff completeness and overclaim rejection.

## Impact

Octet remains the Rust extractor, while Kamacite owns portable canonical receipt identity. Downstream tools can rely on Preserves-backed receipts without making Octet a Preserves authority.
