## Why

Nickel export is now duplicated infrastructure rather than an Octet-specific standards feature.

- `crates/octet-standards/src/nickel_export.rs` already contains a deterministic pure core for export specifications, BLAKE3 source/dependency/output identities, manifests, freshness checks, contract diagnostics, supported formats, and secret-material rejection.
- Mantle independently implements source/dependency hashing, evaluator descriptors, path admission, deterministic receipts, output identity, and bounded non-claims in `src/nickel_export.rs`, but uses its embedded evaluator rather than the `nickel` CLI.
- Cairn shells out to `nickel export`, validates policy semantics, checks generated-file freshness, and packages Nickel as a runtime dependency.
- Trellis repeats typecheck, export, fixture, and generated-file freshness behavior in several Rust scripts.
- Animus repeats multi-format export and freshness comparison in shell and Nix wrappers.

These implementations differ at their imperative evaluator and product-policy edges, but they repeat the same evaluator-neutral contract: declared inputs produce bounded generated bytes whose provenance and freshness are reviewable. Keeping that contract inside Octet forces unrelated repositories either to depend on an evidence/lint product or to continue reimplementing it.

## What Changes

- Create `OnixResearch/nickel-export` as the canonical repository for evaluator-neutral Nickel export contracts.
- Extract a `#![no_std]`/`alloc` functional core for request validation, canonical manifests and receipts, BLAKE3 identities, freshness verification, and fail-closed diagnostics.
- Provide a thin std CLI shell for explicit file reads, `nickel` process invocation, generated-file writes, and check mode; embedded evaluators such as Mantle continue to call the core directly.
- Freeze cross-consumer conformance fixtures from Octet and Mantle, plus script-oriented JSON/TOML/YAML/raw cases derived from Cairn, Trellis, and Animus.
- Pin Octet to one immutable standalone revision and retain only an explicit compatibility facade during migration.
- Require consumer-owned Cairn cutover packages for Mantle, Cairn, Trellis, and Animus rather than mutating those repositories implicitly from Octet.

## Impact

- **New repository**: `OnixResearch/nickel-export`, with canonical core, CLI shell, schemas, fixtures, and release evidence.
- **Octet**: `octet-standards` becomes a consumer and compatibility facade; Octet policy semantics and standards registration remain Octet-owned.
- **Other consumers**: evaluator implementations, product contracts, generated-file destinations, and runtime policy remain in their owning repositories.
- **Compatibility**: selected legacy Octet and Mantle fixture bytes and diagnostics are checked explicitly; arbitrary historical scripts are not assumed equivalent.
- **Claims**: export evidence proves declared input/evaluator/output identity and freshness only. It does not prove policy correctness, deployability, build success, secret absence beyond declared checks, or evaluator correctness.
