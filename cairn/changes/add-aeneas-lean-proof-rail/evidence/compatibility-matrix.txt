# Aeneas compatibility matrix evidence

Requirement: `r[octet.aeneas_lean_proof_rail.pin_upgrade_matrix]`

The typed Nickel matrix at
`standards/proof-rails/aeneas-lean/compatibility-matrix.ncl` binds every
reviewed upgrade dimension: Aeneas, Charon, rustc, Lean, Aeneas library,
schema, and provider profile. Its generated JSON contains eleven canaries:
two live provider canaries and nine pure admission/rejection canaries.

The provider closure now includes:

- exact Aeneas, Charon, Lean, Lake, bubblewrap, and `leantar` identities;
- Mathlib v4.31.0 and the exact Git revisions from its checked manifest;
- a fixed-output Lake dependency closure with
  `sha256-wq4OBVgChJi59Widl+vuAPoq+MNZfFmdJwcsREW5RIo=`;
- path-only root and nested Lake manifests, with network denied at execution;
- an isolated `HOME`, bounded process capture, and
  `MATHLIB_NO_CACHE_ON_UPDATE=1`; and
- a scalar-core staged Aeneas prelude limited to `Aeneas.Data`, `Aeneas.Do`,
  and `Aeneas.Std.Scalar`; broad command, extraction, `Std`, and tactic
  umbrellas are excluded from this canary closure.

The positive fixture executes Charon extraction, Aeneas translation, Lake
compilation of `Llbc.lean`, and the maintained theorem. The false fixture runs
the same stages and must fail in Lean without timeout. Both use fresh work
roots and the denied network namespace.

The combined upgrade gate runs both live fixtures serially and the pure Aeneas
validator suite:

```text
$ nix build --option builders '' --option secret-key-files '' \
    .#checks.x86_64-linux.aeneas-lean-compatibility-matrix --no-link -L

pure compatibility: 13 passed; 0 failed
live compatibility: 2 passed; 0 failed; finished in 451.73s
```

Supporting gates also pass:

```text

    .#checks.x86_64-linux.aeneas-lean-provider-closure --no-link -L
```

The gate establishes executable compatibility for these exact fixtures and
pins. It does not establish translation soundness, Lean soundness, semantic
equivalence, whole-program correctness, or downstream release eligibility.
