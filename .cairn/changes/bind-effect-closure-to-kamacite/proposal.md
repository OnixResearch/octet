## Why

Octet effect closure reports bounded Rust source effects with a small nominal vocabulary. Kamacite owns portable semantic effect-operation identities and closed effect summaries.

No checked handoff currently compares Octet source evidence with one exact Kamacite effect summary. Products must therefore maintain parallel effect vocabularies without deterministic mismatch evidence.

## What Changes

- Add an opt-in Nickel profile for ambient effect closure, explicit semantic-effect emissions, and exact Kamacite operation identities.
- Keep ambient host effects under the existing strict profile. They cannot become semantic operations through mapping.
- Classify explicit semantic-effect emission sites by exact function, call-site, provider, and Kamacite operation identity.
- Compare successful ambient closure and explicit emission evidence with one canonical Kamacite closed effect summary projection.
- Reject stale identities, ambiguous mappings, unknown effects, undeclared observed operations, and role overclaims.
- Emit a deterministic Kamacite handoff projection after Octet verification succeeds.
- Keep Octet source-token closure, Kamacite canonical semantics, and Valence evidence linkage as separate authorities.

## Impact

- **Policy**: New Nickel mapping profile and generated runtime projection.
- **Runner**: An optional Kamacite comparison input for `cargo octet admit` and artifact verification.
- **Core**: Pure mapping admission, comparison, canonical ordering, and deterministic diagnostics.
- **Evidence**: A BLAKE3-bound handoff projection that remains non-authoritative until Kamacite canonicalizes it.
- **Testing**: Positive, negative, drift, default-compatibility, and frozen Kamacite fixtures.

## Out of Scope

- Replacing Octet's source effect vocabulary with Kamacite schemas.
- Loading Kamacite at runtime or making Kamacite a Rust analyzer.
- Proving complete Rust effect closure, semantic determinism, runtime reachability, handler behavior, or release eligibility.
