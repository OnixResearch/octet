## Why

Nix closure receipt enforcement currently accepts a source-root fixture manifest as the digest seam. The flake already emits an `exportReferencesGraph` artifact, but receipts do not have to bind to the graph bytes that Nix generated. This leaves one remaining gap between declared closure identity and direct recursive closure evidence.

## What Changes

- Add generated Nix closure graph digest metadata to proof receipts.
- Teach the Rust proof checker to hash generated `exportReferencesGraph` artifacts with a deterministic graph-aware algorithm instead of treating them as plain fixture text.
- Extend Nickel contracts, generated artifacts, fixtures, Nix manifest package/checks, docs, and tests so receipt validation fails when the graph digest is absent or stale.

## Scope

In scope: local deterministic Nix graph artifacts generated by the existing flake package, receipt metadata, Rust validation, and saved evidence.

Out of scope: remote store attestation, binary-cache signature policy, network fetch policy, and downstream Aspen pin updates.

## Verification

Use focused proof-rail tests, package tests, clippy, policy export/fixture Nix checks, the Nix closure manifest package/check, docs examples, strict OpenSpec validation, and diff hygiene transcripts under this change evidence directory.
