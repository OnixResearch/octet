## Context

The verified proof rail now validates command/source hashes, provenance, verifier/toolchain identity, verifier binary digest, and a build-closure manifest digest. The remaining gap is that the manifest is not tied to a Nix derivation identity or recursive closure graph generated by Nix.

## Decisions

### 1. Nix closure fields stay typed under `receipt_verifier`

**Choice:** Extend `receipt_verifier` with Nix derivation and recursive closure fields.

**Rationale:** Verifier identity, binary, build manifest, and Nix closure are all verifier provenance. Keeping them in one contract keeps Nickel as the typed intent surface and Rust as the deterministic receipt checker.

### 2. Rust validates receipt lines from checked source manifests

**Choice:** Add `proof-verifier-nix-derivation`, `proof-verifier-nix-derivation-blake3`, `proof-verifier-nix-closure`, and `proof-verifier-nix-closure-blake3` lines. Closure digest is recomputed from configured source-root-relative closure manifest paths when those paths are present in checked sources; otherwise configured digest is used as the static obligation.

**Rationale:** The checker remains deterministic and does not shell out to Nix during default receipt-only checks. Nix generation is a separate local-first artifact path.

### 3. Flake exposes a closure-manifest package

**Choice:** Add a Nix package that uses `exportReferencesGraph` for the `tigerstyle-standards` derivation and writes a bounded manifest artifact.

**Rationale:** This makes the closure identity reproducible from Nix and gives reviewers an exact regeneration seam without requiring hidden network or credentials.

## Risks / Trade-offs

- **Digest churn:** Nix output and closure digests can change when source code changes. Mitigation: keep fixture digests explicit and covered by standards fixture checks.
- **Large closure graphs:** Full references graphs can be verbose. Mitigation: fixture uses a bounded manifest path and evidence records command summaries, not huge graph dumps.
